## 思考强度：为什么仍然只有 High / Max

模型卡写了 1–100 的连续 Juice，但托管 Responses API 只收字符串档位 `none / minimal / low / medium / high / xhigh / max`。实测整数 `1 / 25 / 50 / 75 / 100`、字符串 `"50"` 和 `ultra` 全部 HTTP 400。底层对照是 `low = 50`、`high = 75`、`max = 100`，官方把 Codex 六档收成三档：`minimal` / `low` → 50，`medium` / `high` / `xhigh` → 75，`max` / `ultra` → 100。展开成六档滑块，其中三档指向同一个 Juice，没有分辨率。目录因此维持两档：

| Codex 滑块 | 发给 DeepSeek | 模型 Juice |
|---|---|---|
| High | `high` | 75 |
| Max（默认） | `max` | 100 |

路由器把 `low` / `medium` / `high` 折成 `high`，其余（含 `xhigh`、`max`、`ultra`）折成 `max`。

## 升级

```bash
git pull --ff-only
node src/cli.mjs sync
node src/cli.mjs stop && node src/cli.mjs start
node src/cli.mjs doctor
```

随后完全退出（⌘Q）并重开 ChatGPT 桌面端，再新建一个任务。已有任务保留旧模型状态。
